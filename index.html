概览
芯桥通用命令行工具测试平台是基于 Flask 的命令行工具自动化验证系统：把「命令 + 期望返回」写入 Excel 即可对任意 remote 上的命令行工具做自动化校验。 使用流程（参考说明书第 3 章）：① 在 Dashboard 输入 remote ip / host / password 检查测试环境 → ② 上传 Excel 用例并 Run Case → ③ 查看测试结果（表格 + 饼图）与监控结果（多卡折线）→ ④ 检查 dmesg 系统错误。

环境检查 / 固件（Dashboard）
在 Web 端 Dashboard 输入 remote ip / host name / password 后提交，平台调用 remote 上的 Sinexusmi 工具查询 firmware 版本（若未安装 Sinexusmi，后端自动安装 Sinexus_debug 查询）。需要更新时，填入 firmware url 点击更新，远端执行更新程序并回显结果 / 报错（对应说明书 2.1）。

软件栈管理（Full-Stack）
若 remote 缺少 Sinexus 组件或其依赖，则无法测试；缺少 Sinexusmi 则无法监控。在 Web 端输入 remote ip 与 full-stack url，即可在该远端「一键安装 Sinexus 软件栈」（说明书 2.2）。后端用正则匹配解压压缩包并进入目录安装。

用例上传 / 执行（CaseRunner）
平时以 Excel 管理命令行用例：每个 sheet 含 case_id / cmd / expected 三列（均为 string，expected 支持正则）。在 caserunner 页面上传 Excel，返回 load success；点击 Run Case 后，用例同步到远端 remote 并批量执行，输出新的 report dataframe（说明书 2.3 / 2.4）。

测试结果（Result）
测试结束后由中间页面展示全部 case 的匹配结果（dataframe → HTML 表格），并生成结果饼图：匹配成功返回 PASS，失败返回 FAILED（说明书 2.5.1）。失败的用例以红色加粗显示。

监控结果（Monitor）
点击 Run Case 的同时，平台调用 Sinexusmi / Sinexusdebug 监控 silicon 上的 power / clock / memory utilization / spc utilization 并写入 log；多线程并发调用，case 结束时 kill monitor。解析各卡 CSV 后绘制折线图，多卡展示在同一坐标系（说明书 2.4.2 / 2.5.1.2）。
